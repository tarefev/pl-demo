# Как генерируется каждый блок документа (площадка pl-demo-8)

Справка по состоянию на 01.08.2026. Описывает фактическое поведение стенда: из каких
данных собирается каждый блок, что делает код, а что — нейросеть. Код не цитируется,
но указано, где что лежит.

На площадке два конвейера сборки:

- **жалобы и позиция защиты** (апелляционная, кассационная, позиция) — документ
  собирается из секций-блоков по данным карточки дела и линиям защиты;
- **ходатайства** — документ собирает пошаговый визард с живой сборкой: каждый
  ответ адвоката сразу дописывает свой фрагмент.

---

## 1. Общие механизмы (действуют для всех блоков)

**Живая сборка.** Документ пересобирается на каждом шаге, а не в конце. Всё, чего
ещё нет в ответах, стоит жёлтыми метками вида «указать номер дела» — видно, что
осталось заполнить. Пропустить шаг можно, но дыра остаётся видимой.

**Подсветка и прокрутка.** После каждого шага визарда сравниваются старая и новая
сборки: добавленные слова помечаются сиреневым маркером (строго по тексту, новый
абзац — целиком, изменённый — только вставленный фрагмент), полотно документа
прокручивается к первому изменению. Пометки гаснут на следующем шаге, по
«Готово, документ верен» снимаются все.

**Чеклист готовности.** Строка состояния над документом: по каждой части —
«не заполнено / имеются недостатки / готово». Часть с текстовой меткой внутри
считается незавершённой. Клик по пункту прокручивает к части.

**Конструктор блока.** Блоки, собранные из доводов (защитная часть жалоб,
«Основания недопустимости», «Доводы переквалификации»), раскрываются стрелкой в
конструктор: Линия защиты / Тезис / Доводы, у каждого довода — основания с
бейджами (Норма, Практика, Доказательство, Обстоятельство, Факт). Основания
можно удалять и добавлять из базы стенда («+ Основание», «+ Доказательство»).

**Мерж ручных правок.** Если адвокат правил состав оснований руками, при
пересборке (перещёлкивание галок в визарде) его состав сохраняется. Признак
простой: фактический состав отличается от сигнатуры автосборки — значит, трогал
человек. Ручные доводы остаются в конце списка.

**Перегенерация.** Изменения в конструкторе включают кнопку «Обновить текст»:
с подключённой нейросетью текст блока пишется по данным конструктора (промт
`regenerateBlock`, js/prompts.js), без неё — шаблонная склейка. Тексты секций
аналогично: нейросеть по данным карточки либо шаблон.

**Свободный ввод по зонам.** Клик по блоку, подблоку конструктора или шапке
кладёт зону в контекст чата — свободный текст правит именно её (с нейросетью —
переписывание по команде, без — шаблонная приписка).

## 2. Жалобы и позиция защиты

Структура секций задана в js/scenarios.js (`DOC_STRUCTURE`); пустая секция
показывается интерактивной рамкой-плейсхолдером, клик вставляет блок сразу.

### 2.1. Шапка

- **Апелляция / кассация**: адресат — апелляционная (кассационная) инстанция из
  карточки дела, строкой ниже «через суд первой инстанции» (ст. 389.3, 401.3 УПК);
  далее «от адвоката …» с реквизитами, «в интересах …» со статусом доверителя,
  номер дела и ссылка на обжалуемый акт. Чего нет в карточке — жёлтые метки
  «вставить …».
- **Позиция защиты и «другой документ»**: только две строки — «от адвоката …»,
  «в интересах …».

### 2.2. Описание судебного акта первой инстанции (апелляция, кассация)

Источник — приговор из карточки дела: суд, дата, судья, квалификация, наказание,
существо решения. Если данных нет — блок с меткой «Опишите приговор…» для ручного
заполнения. Сразу после этого блока в апелляции автоматически вставляется
**стандартный правовой блок** оснований отмены или изменения приговора
(ст. 297, 302, 389.15 УПК РФ, недопустимость обвинительного уклона, позиции
КС РФ, ст. 17 и 14 УПК РФ) — фиксированный текст из js/scenarios.js.

### 2.3. Обстоятельства дела

Собираются из фабулы эпизодов карточки: вводная фраза «По уголовному делу №…
моему доверителю вменяются следующие деяния», затем краткое описание каждого
эпизода (первые предложения фабулы, эпизоды называются по существу — «по факту
совершения…», не «эпизод 1»). Если эпизодов нет — адвокат вводит фабулу в чат
(она распознаётся и сохраняется в карточку) либо прикладывает DOCX с приговором.
С нейросетью текст секции дописывается промтом `generateSection`.

### 2.4. Позиция по приговору

Если статус признания известен по каждому эпизоду — заполняется автоматически и
молча: короткие формулы «по факту … вину не признал, полагая…» по данным
карточки, без дублирования обстоятельств. Если статус неизвестен — текстовая
метка «заполните позицию по вине».

### 2.5. Защитная часть

Один блок = одна линия защиты. Источники: линии карточки дела (создаются по
практике, своими словами, из библиотеки 104 линий дерева УПК с нормативкой).

Сборка блока: конструктор наполняется из линии — тезис, доводы из пула
аргументов линии, у доводов основания (нормы, практика, доказательства с полем
«что и почему доказывает», обстоятельства). Текст блока генерируется:

- **с нейросетью** — по промту `regenerateBlock`: все доводы с основаниями,
  тексты норм, практика, обстоятельства, сводка дела и предыдущая редакция
  блока (чтобы сохранить ручные правки); генерация идёт **по порядку следования
  блоков в документе**, каждому блоку в контекст передаётся предыдущий текст
  документа, чтобы не повторяться;
- **без нейросети** — шаблонная склейка: тезис, доводы, «Это подтверждается: …».

### 2.6. Просительная часть

Собирается автоматически: вводка по типу документа («…руководствуясь
ст. 389.15, 389.20 УПК РФ, ПРОШУ:») плюс пункт от каждой привязанной линии
(из поля `plea` линии), без дублей.

## 3. Ходатайства (визард)

Определения — js/motion-defs.js, данные перечней — js/motions.js, движок —
js/motion-wizard.js. Блоки документа ходатайства:

### 3.1. Шапка

Собирается по шаблону партнёра-адвоката из карточки дела:

- адресат по стадии: суд + судья (судебное разбирательство) либо орган
  расследования + следователь (следствие; наименование органа не дублируется,
  если уже входит в строку следователя);
- «по уголовному делу №…»;
- «от защитника &lt;статус&gt; &lt;ФИО доверителя&gt;», ФИО адвоката, регистрационный
  номер в реестре, удостоверение, «действующего в защиту интересов…», статус с
  квалификацией («осуждённого по ч. 1 ст. 161 УК РФ» — у осуждённого без оборота
  «в совершении»), адрес для корреспонденции, телефон;
- для ходатайства о мере пресечения — дополнительная строка о действующей мере.

### 3.2. Наименование

Функция от типа и ответов: «Ходатайство об изменении меры пресечения»,
«…о назначении повторной судебной экспертизы» и т. п.

### 3.3. Мотивировка («Обстоятельства дела», блок motion-body)

Всегда начинается двумя вводными абзацами из карточки: «В производстве …
находится уголовное дело №… по признакам преступления …» (суд — в родительном
падеже) и «Защиту интересов … на основании ордера №… от … и соглашения
осуществляет адвокат …». Дальше — предмет по типу ходатайства (см. 3.6).

### 3.4. «Правовое обоснование» (блок motion-body2 / хвост мотивировки)

Полные цитаты норм из справочника `NQ` (js/motion-defs.js) — дословные
формулировки статей УПК, Конституции и постановлений Пленума. Состав зависит от
типа и стадии (например, при переквалификации на следствии — ст. 175, в суде —
ч. 2 ст. 252).

### 3.5. Просительная часть, приложение и подпись

- Вводка сжимает перечень норм ходатайства в одну строку: «На основании
  изложенного и руководствуясь ст. 47, 53, 119–122 УПК РФ, ПРОШУ:» (номера — из
  `MOTION_NORMS` по типу и стадии, 119–122 всегда блоком).
- Пункты просьбы — из шаблона типа, согласованы по числу и падежам (защитнику —
  в дательном, «признать недопустимыми доказательствами…» при нескольких).
- Блок «Приложение и подпись» рендерится **после** просительной части (хвост
  документа): перечень приложений по типу + «Ордер адвоката №… — на 1 л. в
  1 экз.» (в суде к исключению доказательства ордер не прилагается), дата,
  «Защитник ________ / ФИО».

### 3.6. Предмет по типам — что и откуда берётся

| Ходатайство | Из чего собирается предмет |
|---|---|
| **Ознакомление с материалами** | Перечень выбранных материалов делится по разделам с формулой «В связи с необходимостью оказания квалифицированной юридической помощи… прошу предоставить… с материалами данного уголовного дела: …» + «А также с материалами доследственной проверки: …»; пояснение адвоката о материалах — отдельным абзацем (кнопка «Развернуть с помощью ИИ» превращает заметку в абзац, без повтора того, что уже в документе); цитаты п. 11–13 ч. 4 ст. 47 и п. 6–7 ч. 1 ст. 53 УПК; предупреждения об объёме до окончания следствия. |
| **Недопустимость / исключение доказательства** | Один абзац на каждое выбранное доказательство: «…является недопустимым по следующим основаниям: перечень оснований» (обстоятельства — в скобках у основания или общим абзацем, по выбранному режиму); «Это подтверждается» — объединение справочника `INADMISSIBILITY_SUPPORT` (основание → нормы + практика) по выбранным основаниям с дедупликацией; блок — конструкторный («Основания недопустимости»). Различие типов: признание (следствие) цитирует ст. 75 и ч. 3–4 ст. 88, исключение (суд) — ст. 235 с ч. 5. |
| **Явка с повинной** | Реквизиты протокола из формы (дата, том, листы, кто принял), обстоятельства адвоката, цитаты ст. 51 Конституции, ч. 1.1 ст. 144, ст. 75 УПК, Пленум № 55. |
| **Переквалификация** | Вменённая статья — из карточки (свободный ввод); варианты «на что» — строго из справочника `requalification_map.json` (312 записей): нормализация ввода → точный ключ → алиасы → отбрасывание пунктов/части; префикс покушения сохраняется; universal-вариант «покушение на вменённую»; КоАП-варианты отдельным блоком «прекращение в связи с декриминализацией» с переходом в сценарий прекращения; дисклеймер. У варианта — тезис и доводы (контент пары из `REQUALIFY_CONTENT` для демо-дела либо шаблонная заготовка), отмеченные галками доводы живьём встают в документ; блок конструкторный («Доводы переквалификации»). Фабула шага 2 вычищается от того, что уже в документе (позиция по вине, вывод о квалификации). |
| **Приобщение доказательств** | Доказательство + способ получения (адвокатский запрос / опрос / от доверителя / специалист → формула по ч. 3 ст. 86), что подтверждает; цитаты ст. 86, 159, 119. |
| **Истребование документов** | Что, где, за какой период; судьба адвокатского запроса (отказ / нет ответа → свой абзац и приложения); цитаты ст. 86, 21, 159. |
| **Прекращение дела** | Основание из двухуровневого перечня по ст. 133 (реабилитирующие/нет); цитата нормы именно выбранного основания; при нереабилитирующем — обязательное подтверждение согласия доверителя; при реабилитирующем — пункт о праве на реабилитацию. |
| **Возвращение прокурору** | Основание из перечня ч. 1 ст. 237, обоснование адвоката, цитаты ст. 237; прокурор — в дательном падеже из карточки. |
| **Свидетель / эксперт** | Данные лица из формы; ветки: явка обеспечена (ч. 4 ст. 271 — суд не вправе отказать) или вызов повесткой; для эксперта — реквизиты заключения. |
| **Экспертиза** | Вид (первичная/дополнительная/повторная → свои цитаты ст. 207), вид экспертизы из перечня, типовые вопросы по виду (подстановки {лицо} становятся жёлтыми метками), учреждение, реквизиты прежнего заключения. |
| **Следственные действия** | Действие из шести групп; для действий из перечня ч. 2 ст. 29 — предупреждение о судебном порядке ст. 165; цель и обоснование; участие защитника. |
| **Мера пресечения** | Текущая мера и действие (отмена/смягчение), реквизиты решения об избрании, основание, обеспечение новой меры (залог — сумма и залогодатель, домашний арест — адрес и согласие); меры склоняются по падежам («с заключения под стражу на подписку о невыезде»); цитаты ст. 97, 99, 110, Пленум № 41; пункт об освобождении из-под стражи. |
| **Отложение заседания** | Основание из четырёх групп, срок, подтверждающий документ (без него — предупреждение); дата заседания из карточки; просьба согласовать новую дату по телефону адвоката. |
| **Нарушение норм УПК** | Свободный текст нарушения + выбор просьбы (шаблона партнёра нет — своя структура по общей рамке). |

### 3.7. Правовые предохранители

Работают предупреждениями прямо в шаге, в два такта: первый клик предупреждает
(«Всё равно продолжить»), второй пропускает с жёлтой меткой в документе.
Примеры: объём материалов и копирование до окончания следствия, согласие
доверителя при нереабилитирующем прекращении, ст. 165 для судебных действий,
документ при отложении, письменное согласие при опросе.

## 4. Где участвует нейросеть (и что без неё)

| Место | С нейросетью | Без неё |
|---|---|---|
| Текст блока по конструктору | промт `regenerateBlock` | шаблонная склейка |
| Тексты секций жалоб | промт `generateSection` | шаблонные формулы из карточки |
| Правка выбранной зоны из чата | промт `editTarget` | шаблонная приписка |
| Черновики текстовых шагов визарда | «Черновик с ИИ» | заполнение вручную |
| «Развернуть с помощью ИИ» (пояснения) | развёртка заметки с учётом контекста | шаблонное развёртывание |

Ключ, адрес и модель задаются в настройках стенда (js/llm.js); без ключа все
сценарии работают на шаблонах и не ломаются.

## 5. Не действует после отката 31.07 (лежит в ветке `backup/inadm-gate-2026-07-30`)

- гейт «тип доказательства × основание» с отбором норм кодом
  (EVIDENCE_TYPES / INADMISSIBILITY_GROUNDS_MAP / COMMON-нормы);
- редактор-нейросеть по промту Никко (per-evidence вызовы);
- чекбоксы на шаге режима обстоятельств, шаг 1 без тома и листов, чистка норм.
